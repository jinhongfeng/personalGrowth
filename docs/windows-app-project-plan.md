# Windows 个人成长与密码管理应用项目计划书

## 1. 项目概述

### 1.1 项目名称
个人成长与活人感恢复助手（暂定名）

### 1.2 项目定位
这是一个面向个人使用的 Windows 桌面应用，核心目标是帮助用户：

1. 记录并追踪自己的成长提升，如篮球、健身、睡眠、学习等。
2. 作为个人密码箱，记录网站、用户名、密码及相关备注。
3. 提供“找回活人感”页面，结合用户性格与当前状态，随机生成适合执行的行动建议。

### 1.3 项目目标

本项目不是单纯的记录工具，而是一个“个人状态管理器”。它需要同时解决三类问题：

1. `记录问题`：把零散的成长数据与账号信息稳定保存下来。
2. `反馈问题`：让用户知道自己是否在进步，而不是只存数据。
3. `行动问题`：当用户状态低、无聊、麻木或拖延时，给出可执行的下一步。

### 1.4 目标用户

适合以下类型的个人用户：

1. 希望长期记录成长但不想使用复杂 SaaS 的用户。
2. 需要把账号密码、站点信息集中管理的个人用户。
3. 偶尔出现空虚、无力、缺乏目标感，希望系统给出行动建议的用户。

## 2. 产品核心模块

### 2.1 成长记录模块

#### 目标
围绕“提升自己”建立可持续记录体系。

#### 支持记录的方向

1. 篮球
   - 训练时长
   - 投篮命中数
   - 运球练习
   - 对抗/实战记录
   - 主观状态评分

2. 健身
   - 训练部位
   - 动作名称
   - 组数、次数、重量
   - 有氧时长
   - 体重、体脂、围度

3. 睡眠
   - 入睡时间
   - 起床时间
   - 睡眠时长
   - 睡眠质量评分
   - 熬夜标记

4. 学习
   - 学习主题
   - 学习时长
   - 完成内容
   - 输出内容
   - 专注度评分

#### 核心功能

1. 快速新增记录
2. 按分类查看历史记录
3. 周/月统计趋势图
4. 目标设定与完成率展示
5. 标签体系，例如 `高强度`、`低状态`、`复盘`、`突破`

### 2.2 密码箱模块

#### 目标
集中管理用户常用网站与账号信息。

#### 记录内容

1. 网站名称
2. 网站地址
3. 用户名/邮箱
4. 密码
5. 备注
6. 分类标签，例如 `工作`、`社交`、`支付`
7. 最近更新时间

#### 核心功能

1. 新增、编辑、删除账号信息
2. 一键复制用户名、密码
3. 搜索和筛选
4. 密码强度提醒
5. 重复密码提示
6. 重要条目标星

#### 安全要求

密码箱属于高敏感模块，必须从第一版就考虑安全：

1. 本地数据库加密
2. 主密码解锁
3. 自动锁定
4. 剪贴板复制超时清除
5. 本地备份文件加密导出

### 2.3 找回活人感模块

#### 目标
在用户低能量、迷茫、麻木、无聊时，给出可执行、低门槛、个性化的行动建议。

#### 设计思路
这个页面不应只是“随机任务列表”，而应结合用户画像、当前状态和现实约束生成建议。

#### 用户画像建议维度

1. 性格倾向
   - 内向 / 外向
   - 理性 / 感性
   - 独处恢复 / 社交恢复

2. 当前状态
   - 精力低
   - 心情差
   - 拖延严重
   - 大脑混乱
   - 想进步但起不来

3. 可用资源
   - 可用时间：5 分钟 / 15 分钟 / 30 分钟 / 1 小时
   - 地点：室内 / 室外
   - 是否可社交
   - 是否需要花钱

#### 建议任务类型

1. 身体唤醒类
   - 下楼走 10 分钟
   - 做 20 个深蹲
   - 去球场投 30 个球

2. 环境整理类
   - 收拾桌面 5 分钟
   - 扔掉一个无用物品
   - 清理电脑桌面

3. 认知恢复类
   - 写 3 条现在真实的感受
   - 列出今天最重要的一件事
   - 关闭手机 20 分钟专注一件小任务

4. 社会连接类
   - 给一个朋友发一句真实问候
   - 联系一个很久没联系的人
   - 约一次篮球或散步

5. 微成长类
   - 背 10 个单词
   - 读书 5 页
   - 复盘昨天一个问题

#### 核心功能

1. 用户填写个人画像
2. 按状态筛选任务建议
3. 点击“随机给我一个”
4. 支持“不想做，换一个”
5. 完成后记录感受和状态变化
6. 长期统计哪些任务对用户最有效

## 3. 版本规划

### 3.1 第一阶段：MVP 版本

先做最小可用版本，目标是能真正开始用。

#### 范围

1. 成长记录基础增删改查
2. 密码箱基础增删改查
3. 找回活人感页面基础推荐
4. 本地数据存储
5. 桌面端基础 UI

#### MVP 不必一开始做的内容

1. 云同步
2. 多设备同步
3. 高级图表系统
4. AI 智能建议
5. 浏览器插件联动

### 3.2 第二阶段：增强版本

1. 更完整的统计分析
2. 密码安全评分
3. 用户画像问卷
4. 智能任务推荐策略
5. 本地备份/导入/导出

### 3.3 第三阶段：高级版本

1. AI 复盘建议
2. AI 生成“今日恢复计划”
3. 多维度习惯关联分析
4. 数据可视化仪表盘
5. 可选云同步能力

## 4. 技术方案建议

### 4.1 推荐技术栈

如果目标是 Windows 桌面应用，推荐：

1. `Tauri + React + TypeScript`
2. 本地数据库使用 `SQLite`
3. 敏感字段使用加密存储
4. 图表使用成熟图表库

#### 推荐原因

1. Tauri 打包后更轻，适合桌面工具。
2. React 生态成熟，后续扩展快。
3. SQLite 适合本地个人数据管理。
4. TypeScript 便于后期维护。

### 4.2 数据存储建议

#### 主要数据表

1. `users_profile`
   - 用户昵称
   - 性格倾向
   - 偏好设置
   - 当前目标

2. `growth_records`
   - 分类
   - 项目名称
   - 数值数据
   - 文本备注
   - 时间
   - 状态评分

3. `password_vault`
   - 网站名
   - URL
   - 用户名
   - 加密密码
   - 备注
   - 标签
   - 更新时间

4. `alive_tasks`
   - 任务名称
   - 任务类型
   - 适合人群
   - 时长
   - 场景
   - 难度

5. `alive_task_logs`
   - 执行任务
   - 执行时间
   - 执行前状态
   - 执行后状态
   - 主观反馈

### 4.3 安全设计

密码功能不能按普通笔记设计，建议至少包含：

1. 主密码 + 本地派生密钥
2. 数据库存储时字段加密
3. 应用闲置自动锁定
4. 打开应用时需要身份验证
5. 导出备份时再次验证主密码

## 5. 页面设计建议

### 5.1 首页仪表盘

展示用户当日状态与关键入口：

1. 今日成长记录概览
2. 睡眠与学习简报
3. 本周目标完成率
4. “今天给我一个行动”按钮
5. 最近密码箱更新提醒

### 5.2 成长记录页

建议用标签页或分区布局：

1. 篮球
2. 健身
3. 睡眠
4. 学习
5. 全部记录

### 5.3 密码箱页

建议采用左侧列表 + 右侧详情结构：

1. 左侧展示站点列表
2. 顶部提供搜索和标签筛选
3. 右侧查看账号详情
4. 提供复制、编辑、标星、删除

### 5.4 找回活人感页

建议分三块：

1. 当前状态选择区
2. 随机任务展示区
3. 执行反馈区

这个页面的体验重点是：

1. 操作非常轻
2. 文案不要像打卡系统
3. 推荐结果要像“现在就能做”

## 6. 关键非功能要求

### 6.1 易用性

1. 3 步内完成记录
2. 常用操作支持快捷入口
3. 表单尽量少输入、多选择

### 6.2 性能

1. 启动速度快
2. 本地查询响应快
3. 图表加载平稳

### 6.3 安全性

1. 密码数据默认加密
2. 锁屏或最小化后可自动锁定
3. 剪贴板敏感信息短时清理

### 6.4 可维护性

1. 模块边界清晰
2. 记录模块和密码模块分离
3. 推荐策略可独立迭代

## 7. 风险与应对

### 风险 1：功能太多，第一版难以落地
应对：
只做 MVP，先保证能稳定记录、查看、加密保存。

### 风险 2：密码箱安全设计不足
应对：
第一版就引入主密码、加密存储、自动锁定。

### 风险 3：找回活人感功能过于空泛
应对：
先从规则推荐做起，根据性格、时间、地点、精力进行任务筛选，不急着上 AI。

### 风险 4：用户持续使用率低
应对：
减少输入成本，增加反馈感和成就感，不把产品做成负担。

## 9. 成功标准

如果项目达到以下结果，说明第一阶段成功：

1. 用户每天能快速记录成长数据。
2. 用户能安全保存并查找常用账号密码。
3. 用户在低状态时能通过“找回活人感”页面获得可执行建议。
4. 应用稳定运行于 Windows，本地数据可持续保存。

## 10. 结论

这个项目的价值，不在于做一个“大而全”的工具，而在于把三个很真实的问题放在一个个人系统里解决：

1. 我有没有变好。
2. 我的重要信息是否被稳定管理。
3. 我状态很差的时候，下一步该做什么。

因此，建议先做一个强调 `轻记录 + 强反馈 + 安全存储 + 低门槛行动建议` 的 Windows 桌面应用，再逐步增加智能化能力。
